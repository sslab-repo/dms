# migrations

This directory contains the **PostgreSQL schema migrations** for the Dataset Platform.

## What migrations are

Migrations are SQL files that create and evolve the database schema in a predictable order. Each file is numbered so it runs once and in sequence.

## Files

| File | Purpose |
|---|---|
| `001_init.sql` | Creates the initial schema: `datasets`, `labels`, `pseudo_queries`, and `files` tables with indexes. Also adds `embedding_json` for vector storage. |
| `002_files_storagepath_nullable.sql` | Makes `files.storage_path` nullable (default empty string) so rows can be created before the file is uploaded. |
| `003_add_unique_constraints.sql` | Prevents duplicate pseudo-queries per dataset, indexes `labels(label_name)`, and adds `expected_files` to `datasets` so the upload flow knows when all files have arrived. |
| `004_add_dataset_profiles.sql` | Adds `profile_json` (JSONB) and `processing_stage` (text) to `datasets` for richer progress tracking during AI analysis. |
| `005_add_ai_confidence_caveats.sql` | Adds `ai_confidence` (real) and `ai_caveats` (text array) so researchers know when metadata was inferred from bounded samples. |
| `006_materialized_search_vector.sql` | Converts `datasets.search_vector` from a generated column to a plain `tsvector`, recreates the GIN index, and backfills labels/pseudo-queries into keyword search. |
| `007_auth_users.sql` | Adds `users`, dataset `owner_id`, and the owner index used by auth-protected mutations. |

## Key tables

- **`datasets`** — core metadata for every dataset (name, researcher, summary, modality, type, size, status, AI results, keyword `search_vector`, semantic `embedding_json`).
- **`labels`** — AI-generated class names and proportions per dataset (Weka-style).
- **`pseudo_queries`** — example search questions generated by AI to reduce vocabulary mismatch.
- **`files`** — tracks each uploaded file, its path on disk, size, and upload status.
- **`users`** — local username/password accounts with admin or researcher roles.

## How to run migrations

Migrations are typically applied manually with a tool like `psql` or `migrate`. The backend connects to the database defined in [`config/config.go`](../config).
